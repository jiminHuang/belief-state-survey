# Monthly update procedure

The list is updated once a month, in the first week, for the month that just ended. The README is generated; never edit it by hand.

1. **Candidates.** `cd lit_search && python3 monthly_update.py YYYY-MM` runs every keyword query in `config.json` on OpenAlex for that month and a phrase search on Hugging Face Papers, applies the rule screen (I1 LLM term, E1 off-domain, I2 two topic terms), removes everything already screened, and writes `runs/updates/YYYY-MM/candidates.csv` with a `read` flag (score >= 10, or *belief* in title or abstract, or a world-model paper with score >= 7). An OpenAlex key goes in `lit_search/.openalex_key` (gitignored; never commit it or copy it anywhere else).
2. **Full-text screening.** Read every candidate flagged `read` in full. A paper is included if it concerns a language-model agent (or a component used by one) and constructs, revises, tests, learns, or evaluates an explicit state carried between decisions, or documents a failure of such a state. Write `runs/updates/YYYY-MM/screen.csv` with the 16 master columns: `arxiv_id,date,title_short,decision,who_maintains_belief,credited_object,revision_signal,belief_level_metrics,survey_section,role_in_survey,note,bibkey,first_author,title,venue,evidence`. Codes: `who_maintains_belief` in {context, external memory, prob. memory, ext. filter, written, world model, n/a}; `credited_object` in {none, output, trajectory, interaction (action), interaction (memory op), world-model loss, state}; `survey_section` 3 state, 4 transition, 5 learning signal, 6 evidence, 7 evaluation; `evidence` P or A. For any paper coded `state`, read the method section and record in `revision_signal` exactly what the belief is scored against (own next observation, reconstruction, simulator state, teacher, calibration target, known answer). Validate: 16 fields per row, no spaces in `bibkey`, quoted commas.
3. **Merge.** `python3 merge_update.py YYYY-MM` writes the next master version, builds BibTeX from the arXiv API (titles must come from the API, not be typed), adds a line to `UPDATES.md`, and regenerates the README.
4. **Check and publish.** Skim the README diff, add new belief-credited systems to `AT_A_GLANCE` in `make_readme.py` if they take their signal from a new source, commit, push. Once a quarter, deposit a new version on Zenodo under the same concept DOI.

If an update changes a claim of the survey (as ReBel did in September 2026), say so in `UPDATES.md` and open an issue titled "claim affected".
